CI for LLM evals

Your eval got worse.
Know before you ship.

Eval Diff compares two eval runs, flags regressions, and fails CI when quality drops. No dashboard to configure. One command, one answer.

Try it in the browser Read the code ↗
pip install eval-diff
eval-diff baseline.json candidate.json
Matched: 3  Regressions: 2  Only A: 0  Only B: 0

Regressions:
  s2: suspicion rose 0.230
  s3: new flags: unparsed

# exit 1 when --fail-on-regression is set

What it catches

Four ways an eval can regress.

A regression is not just a lower average. These are the cases Eval Diff reports.

01

Suspicion rose

On eval-triage rows, a monitor suspicion score rising past the threshold counts as worse.

default +0.15
02

Score dropped

On quality-style runs, a score falling past the threshold is a regression.

default −0.10
03

Status flipped

A sample that passed in the baseline and fails in the candidate is always worse.

pass → fail
04

New flags

Any flag present in the candidate that was not in the baseline is reported.

unparsed, failed

Supported inputs

Three formats, one comparison.

eval-triage

Flat list of rows with sample_id and score. Suspicion rises are regressions.

promptfoo

results.results with score and success. Score drops and pass→fail flips are regressions.

legacy

Object with samples carrying score, suspicion, status and flags.

Auto-detection is on by default. Force a format with --format.

In your pipeline

Fail the build when quality drops.

One flag turns Eval Diff into a CI gate. Write a markdown report at the same time if you want it in the PR.

terminal
eval-diff baseline.json candidate.json \
  -m report.md \
  --fail-on-regression
